# Electronics Subsystem: BaseCode V1.1 Firmware Documentation

## Overview & Objectives
BaseCode V1.1 builds upon the BaseCode V1.0 bare-metal polling architecture for the RoboManipal RoboCup SML/@work 2026 KARMA base, introducing electrical and mechanical hardware safety protections. This version integrates software-enforced duty cycle clamping to protect brushed DC motors and MD30C drivers, and implements hardware pin mirroring on Motor 3 direction control to bypass a compromised PCB trace on the development chassis.

Key engineering objectives:
* Enforce a hard 50% maximum PWM duty cycle ceiling (`MOTOR_MAX_PWM_LIMIT`) to prevent high-current stall damage.
* Mirror the Motor 3 DIR signal to auxiliary GPIO pins (PB10 and PB15) alongside PB2 to resolve intermittent track discontinuity on the PCB.
* Maintain backward-compatible 50 Hz JSON telemetry and ASCII command reception over USB CDC with the companion NVIDIA Jetson Orin.

## Technical Specifications & Bill of Materials (BOM)

### System Specifications
* **Microcontroller:** STM32F411CEU6 (WeAct Black Pill), ARM Cortex-M4 @ 96 MHz, 512 KB Flash, 128 KB SRAM.
* **Control Loop Topology:** Bare-metal polling loop (`robot_loop()`).
* **Motor Protection Ceiling:** 50% Maximum ARR (`duty <= period / 2`), commanded speed clamped to $[-500, 500]$.
* **Motor PWM Frequency:** 20 kHz generated by TIM5 (Channels 1 to 4).
* **Direction Pin Redundancy:** PB2 primary, mirrored to PB10 (adjacent pin) and PB15 (legacy V0.0 pin).
* **Sensors:** 3-channel dead-wheel quadrature encoders (TIM4, TIM3, TIM2), BNO085 9-DOF IMU over I2C3.

## Design & Architecture

### Motor Driver Safety Clamping
In `motor.c`, high inrush currents and gearbox shock loads are mitigated through programmatic saturation bounds:

```{code-block} c
void motor_set(uint8_t motor_id, int16_t speed) {
    if (motor_id > 3) return;

    /* Clamp commanded speed to safe maximum bound */
    if (speed >  MOTOR_MAX_PWM_LIMIT) speed =  MOTOR_MAX_PWM_LIMIT;
    if (speed < -MOTOR_MAX_PWM_LIMIT) speed = -MOTOR_MAX_PWM_LIMIT;

    /* Set primary and redundant direction lines */
    if (speed > 0) {
        HAL_GPIO_WritePin(s_motors[motor_id].dir_port, s_motors[motor_id].dir_pin, GPIO_PIN_SET);
        if (motor_id == 2) {
            HAL_GPIO_WritePin(GPIOB, GPIO_PIN_10 | GPIO_PIN_15, GPIO_PIN_SET);
        }
    } else if (speed < 0) {
        HAL_GPIO_WritePin(s_motors[motor_id].dir_port, s_motors[motor_id].dir_pin, GPIO_PIN_RESET);
        if (motor_id == 2) {
            HAL_GPIO_WritePin(GPIOB, GPIO_PIN_10 | GPIO_PIN_15, GPIO_PIN_RESET);
        }
    }

    uint32_t mag = (speed < 0) ? (uint32_t)(-speed) : (uint32_t)speed;
    uint32_t period = __HAL_TIM_GET_AUTORELOAD(s_htim);
    uint32_t duty = (uint32_t)(((uint64_t)mag * (uint64_t)period) / 1000ULL);

    /* Hard ceiling: duty cycle never exceeds 50% ARR */
    if (duty > period / 2) {
        duty = period / 2;
    }

    __HAL_TIM_SET_COMPARE(s_htim, s_motors[motor_id].tim_channel, duty);
}
```

### Kinematics & Odometry Math
The odometry calculations follow the dual-encoder midpoint arc model:
```{math}
\Delta s = \frac{\Delta s_{\text{left}} + \Delta s_{\text{right}}}{2}, \quad \Delta \theta = \frac{\Delta s_{\text{right}} - \Delta s_{\text{left}}}{W}
```
where $R = 35.0\text{ mm}$ and $W = 150.0\text{ mm}$.

### ROS 2 Interface Topics
* `/cmd_vel` (`geometry_msgs/msg/Twist`): Inbound command velocity vector mapped to 4-wheel PWM.
* `/odom` (`nav_msgs/msg/Odometry`): Outbound 50 Hz filtered odometry estimate.
* `/imu/data` (`sensor_msgs/msg/Imu`): Outbound 50 Hz BNO085 orientation quaternion and acceleration.

## Future Work / Known Limitations
* **Retained Bare-Metal Bottlenecks:** Although V1.1 fixes driver electrical overstress and PCB track issues, it retains all architectural flaws of V1.0: USB buffer race conditions on `CDC_Transmit_FS()`, lack of I2C bus recovery bit-banging, and loop timing jitter.
* **Deprecation Notice:** BaseCode V1.1 is deprecated and superseded by BaseCode V2.0 (Zero-Heap FreeRTOS + 2D State Matrix Architecture).
